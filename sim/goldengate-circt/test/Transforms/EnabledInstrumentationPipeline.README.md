# Enabled source instrumentation composition

`compileInstrumentationSourceToControl` starts with the scalar LowForm target
and the same retained annotations as the Scala compiler. It composes enabled
AutoCounter CSV selection, selected PrintSynthesis, dynamic trigger accounting,
global reset wiring, rational clock metadata, actual model FAME, constructor
binding, shared MMIO allocation, buffered CPU AXI transport and driver/decoder
collateral. All work occurs on a private IR root; failures preserve the input
circuit and caller outputs. The selected catalog contains every CSV and Print
constructor, followed by the CPU stream engine. Another original platform
bridge is rejected; this API does not omit it from an allegedly complete map.

`EnabledInstrumentationPipeline.fir` has two target domains with 1/1 and 1/3
clock ownership, target registers, hierarchical source events, both accumulate
and identity counters, a real state-derived Print record, and reset-masked
credit/debit trigger sources. Inputs are complete stable data/clock tokens;
independent output stalls provide backpressure. Clock generator phase is outside
this boundary. The fixture uses internal trigger annotations at the LowForm
handoff, matching the SFC conversion stage.

`EnabledInstrumentationPipelineOracle.scala` invokes unchanged SFC target
transforms, including actual enabled PrintSynthesis and FAMETransform. It binds
the actual resulting target into unchanged AutoCounterBridgeModule,
PrintBridgeModule, HasWidgets and CPUManagedStreamEngine implementations. Its
only wrapper changes are external channel exposure and the checked ordered
TargetBox clock-pin link already used by the CSV oracle. Production Scala
sources and immutable goldens are not edited.

`EnabledInstrumentationPipelineCompare.py` checks retained constructor/channel,
reset/clock/gate contracts with explicit wrapper-name and concrete PrintPort
serialization-hint normalization. It compares externally observable cycle
behavior, live CPU DMA payloads and MMIO samples against SFC with independent
initialization seeds. Unwritten queue payloads are never compared while invalid;
target resets precede state observations. The comparison reads counters only
when their real countersready flag is asserted. The standard
`InstrumentationHeaderCompare.py` compiles both sets of constructors against the
actual driver ABI and compares all semantic constructor arguments.

`EnabledInstrumentationPipelineMutation.py` compiles actual emitted RTL with a
Print argument bit fault and a disabled target trigger synchronizer, requiring
both to fail the same replay. A perturbation applied only to invalid Print
argument payloads must pass. `EnabledInstrumentationPipelineCLI.py` checks the
complete source compiler and five early/late failures without publishing partial
control products. Its direct-input variant prints `topEvent` while the same
source still drives target state, triggers and counters. ChannelExcision splits
that source into independent model and direct-Print token branches. The graph
pass promotes the exclusive scalar bridge-to-bridge identity into one whole
Decoupled connect and transfers payload annotations and inner symbols. Unsplit
fanout, duplicate/unknown channel ownership and unsupported metadata reject
atomically.

Use `--direct-print-input` on the comparison and mutation scripts for this
variant. The comparison derives and checks the two branch roles under the same
source fanout: native and SFC statement order assign opposite autogenerated
`topEvent`/`topEvent_1` ordinals. Only this checked bijection and its corresponding
wrapper input name are normalized; constructor, clock/reset, payload widths,
model role and source-fanout membership remain strict. Nine independently
stalled stable token inputs exercise the two branches through actual Print DMA
and CSV sampling. Compiled emitted argument crosswires and ready corruption
must fail; differences restricted to invalid payloads must pass.

This is scoped supporting compiler evidence. F2 shell composition with original
platform bridges, a Linux-capable enabled representative, separate complete
Jasper LEC and SEC, checked CSV/Print userspace output and clean poweroff remain
required. These tests do not populate required-feature acceptance receipts.
